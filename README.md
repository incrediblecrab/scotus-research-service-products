# scotus-research-service-products

This repository builds Hugging Face datasets of the twenty-four Supreme Court document collections on [www.supremecourt.gov](https://www.supremecourt.gov), one dataset per column of the site's footer and one config per collection: [scotus-opinions](https://huggingface.co/datasets/incrediblecrab/scotus-opinions) (Opinions of the Court, Opinions Relating to Orders, In-Chambers Opinions, U. S. Reports, Online Sources Cited in Opinions, Media Files Cited in Opinions), [scotus-oral-arguments](https://huggingface.co/datasets/incrediblecrab/scotus-oral-arguments) (Argument Transcripts, Calendars and Lists, Argument Audio), [scotus-case-documents](https://huggingface.co/datasets/incrediblecrab/scotus-case-documents) (Orders of the Court, Orders by Circuit, Granted/Noted Cases List, Journal, Original Jurisdiction Records & Briefs), [scotus-news-media](https://huggingface.co/datasets/incrediblecrab/scotus-news-media) (Press Releases, Media Advisories, Speeches, Chief Justice's Year-End Reports, A Reporter's Guide to Applications, Services for News Media), [scotus-filing-and-rules](https://huggingface.co/datasets/incrediblecrab/scotus-filing-and-rules) (Rules and Guidance, Electronic Filing Documents, Supreme Court Bar Documents) and [scotus-about](https://huggingface.co/datasets/incrediblecrab/scotus-about) (About the Court). A seventh dataset, [scotus-cases](https://huggingface.co/datasets/incrediblecrab/scotus-cases), is built from the first three and the Court's docket pages: one row per case in each term, with its docket page, opinions, argument transcripts and argument audio. Local builds go to `local-data/`, which Git ignores.

**Objective:** a verbatim record of what the Court published. A row is one listed file: its bytes as served, its text as the extractor printed it, and the listing entries that link it. Nothing is corrected, normalized or generated; the pipeline runs no OCR or language model. In scotus-cases a row is one docket in one term: its docket page as served and the fields parsed from it, the opinion and transcript rows of the document datasets that name the docket, copied with their text (only the case's own pages where one file of the United States Reports holds many opinions, and for a case no listing gives an opinion, as before OT2017, the pages of the Reports whose caption names it), and the MP3 addresses on the Court's argument audio pages; docket numbers are written one way, so that `141-Orig` and `22O141` are one case. Each dataset card states the rules and gaps.

**Inputs:** the collection pages and their files, and for scotus-cases the docket and argument audio pages, requested at least 1.1 seconds apart, because robots.txt sets `Crawl-delay: 1`, by a user agent naming this repository, never via a redirect or a disallowed path.

**Files:**

- [`scotus_products/`](scotus_products/README.md): the pipeline package
- [`tests/`](tests/README.md): offline tests
- [`pyproject.toml`](pyproject.toml): pinned dependencies; PDFs also need poppler
- [`.github/workflows/pipeline.yml`](.github/workflows/pipeline.yml): the schedule that keeps the datasets current

**Try it:** `pip install .`, then `python -m scotus_products run --dataset in-chambers-opinions --local /tmp/scotus`, which writes `/tmp/scotus/scotus-opinions/in-chambers-opinions/` as the Hub holds it; `python -m scotus_products verify --dataset in-chambers-opinions --local /tmp/scotus --deep --live` also checks the live sources. `python -m scotus_products.cases run --local /tmp/scotus --terms OT2025 --budget-minutes 5` builds the term's cases from the Hub's document datasets into `/tmp/scotus/scotus-cases/`; `--sources-local local-data` reads a local build of them instead.

**Schedule:** GitHub Actions runs [`pipeline.yml`](.github/workflows/pipeline.yml) at 00:00 and 12:00 UTC; GitHub starts scheduled runs late when it is busy, often by hours. A run first builds scotus-cases for up to 60 minutes from the document datasets as the Hub holds them, asking only for the docket pages that are due, so its rows lag the documents by one run; then it syncs all twenty-four collections in turn within 290 minutes, with 10 minutes kept for each collection still to come, then verifies each collection it changed against its manifest. Argument Audio comes last, so its MP3 backfill takes only the time the other collections leave. A run whose sync or cases build ran out of time, as a backfill does, starts the next run itself, but only if that job fetched something. Writes use Hugging Face Trusted Publishing: the job's OIDC token is traded for a short-lived token scoped to the dataset being written, so no Hugging Face token is stored in the repository. Each dataset's Trusted Publisher names this repository, branch `main` and `pipeline.yml`. On the runner, poppler comes from Ubuntu's `poppler-utils`, which is older than the Homebrew poppler of the local build; each row's `extractor` column names the version that produced its text, and `verify --deep` should run with the version the rows name. A manual run (**Run workflow**) takes a collection, a budget, a budget for the cases build (0 skips it) and extra run arguments; with extra arguments it skips verify and the cases build and never starts another run. The `inactivity` job fails once the repository has gone 50 days without a commit, because GitHub disables the schedule of a public repository after 60 days without activity. A term page shows another term where its `Term Year` label names another, or where fewer than half of its dated entries fall in its term, and such a page is read again at `?reread=1`, a query string the Court's pages ignore and its CDN caches apart. On September 27, 2026 the CDN answered `/oral_arguments/argument_audio/2017` with its copy of the October Term 2025 page (GitHub's runner was served the right page), and `?reread=1` brought the 2017 page from the origin. Later that day a runner was served `/orders/ordersbycircuit/22` with the label of 2022 and the 31 orders of October Term 2023, and that run, which did not yet read dates, delisted the 32 orders of 2022 and gave the 2023 orders the term 2022; the next run was served the right page, relisted the 32 and gave the 31 back the term 2023. On the rows the Hub listed that day, every other term page had at least 95% of its dated entries in its term; the rest are dated October 1 to 4, before the first Monday of October, which the Court files under the term that is ending. The listing records such a page as `reread`, with `shown_by` naming the check that found it, and the cases build reads the argument audio listing again where its label shows another term. Where the re-read does not show the page's term either, the page is held: the run takes nothing from it, leaves the rows the last complete listing found there as they are, delists nothing in that collection, and shows a warning on the run's page, and the next run reads the page again. Neither check can catch an older copy of a page that shows the page's own term: the same day a runner was served a copy of `/opinions/slipopinion/17` that linked 23 slip opinions of March to June 2018, where the current page links four preliminary prints that answer 404; that run added the 23 as rows, and the next run, served the current page, marked them listed = false.
